# ТЕХНИЧЕСКАЯ СПЕЦИФИКАЦИЯ: LIFETIMES В RUST

**Версия:** 2.0 | **Статус:** Обязательный стандарт

## ПРИНЦИП ПРИНЯТИЯ РЕШЕНИЙ

**Золотое правило:** Минимально достаточная сложность lifetime для максимально точного выражения семантики

**Иерархия:** `IMPLICIT → ANONYMOUS '_ → NAMED → STATIC`

## АЛГОРИТМ ВЫБОРА

1. **Есть заимствования?** НЕТ → `implicit` | ДА → шаг 2
2. **Количество references?** 1 → `'_` | 2+ → `named`  
3. **Область действия?** Метод → `'_` | Модуль/Public → `named` | Глобал → `'static`
4. **Публичный API?** Приватный → `'_` | Публичный → `named`

## ТЕХНИЧЕСКИЕ КРИТЕРИИ

### IMPLICIT - обязательно

- Owned параметры: `fn process(data: Vec<String>) -> String`
- Методы без заимствований: `fn calculate(&self) -> i32`

### ANONYMOUS `'_` - обязательно

- Одиночные заимствования: `fn get(&self) -> &'_ str`
- Приватные методы: `fn process(&mut self) -> Processor<'_>`
- **Запрещено:** связывание 2+ параметров, публичные API

### NAMED - обязательно

- Публичные API: `pub fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`
- Struct с заимствованиями: `pub struct Parser<'input> { data: &'input str }`
- Связывание 2+ параметров
- **Запрещено:** одиночные простые заимствования

### STATIC - обязательно

- Литералы: `const CONFIG: &'static str = "config"`
- Глобальные данные: `static GLOBAL: AtomicUsize`
- **Запрещено:** обычные заимствования, "решение проблем"

## АРХИТЕКТУРНАЯ СЕМАНТИКА NAMED LIFETIMES

**Принцип:** Named lifetimes описывают АРХИТЕКТУРНУЮ РОЛЬ, не дублируют типы

### Категории хороших имен

- **Поток данных:** `'input`, `'output`, `'primary`, `'fallback`
- **Временные:** `'session`, `'scope`, `'storage`  
- **Функциональные:** `'content`, `'schema`, `'template`, `'context`
- **Отношения:** `'parent`, `'child`, `'left`, `'right`

### Антипаттерны

```rust
// ❌ Дублирование типа
fn process<'config>(cfg: &'config Config)

// ✅ Архитектурная роль  
fn process<'settings>(cfg: &'settings Config)
```

### Критерии качества

- Длина: 3-8 символов
- Семантика: архитектурная роль
- Уникальность: не дублирует типы
- Читаемость: понятно без комментариев

## КРИТИЧЕСКИЕ ОШИБКИ

- **Избыточная сложность:** `fn simple<'a>(data: &'a str) -> &'a str` вместо `fn simple(data: &str) -> &str`
- **Публичный API без named:** `pub fn process(a: &str, b: &str)` вместо `pub fn process<'input>(...)`
- **Неправильный static:** утечки памяти для локальных данных
- **Дублирование типов:** `'matcher RegexMatcher` вместо `'pattern RegexMatcher`

## ЧЕКЛИСТ CODE REVIEW

Для каждого lifetime:

- [ ] Минимальная достаточная сложность?
- [ ] Соответствует публичности?  
- [ ] Named описывает архитектурную роль?
- [ ] Имя 3-8 символов, не дублирует тип?

**Быстрая диагностика:** Заимствования? НЕТ→implicit | Одно→'_' | Публичный→named | Глобальный→'static

**Критерий качества:** Код читается как техническая документация - каждый lifetime точно выражает архитектурные намерения
