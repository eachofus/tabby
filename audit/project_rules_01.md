# Правила проекта Tabby

## Специализация проекта

- **Основной язык**: Rust
- **Фокус**: Работа преимущественно с модулями на Rust
- **Архитектура**: Микросервисная архитектура с четким разделением ответственности
- **Назначение**: Локальный ИИ-ассистент для разработчиков с функциями автодополнения кода и чата

## Эволюция проекта

Tabby прошел следующие основные этапы развития:

- **v0.2-0.3**: Базовая функциональность автодополнения кода, первая версия RAG
- **v0.4-0.6**: Расширение поддержки языков, улучшение UI, распределенные вычисления
- **v0.7-0.9**: Добавление системы пользователей, безопасности, SSO и командных функций
- **v0.10-0.12**: Улучшение мониторинга, отчетности и HTTP API интеграций
- **v0.13-0.15**: Развитие Answer Engine, интеграции с репозиториями, кодовый браузер
- **v0.16-0.18**: Улучшение интерфейсов, управление доступом, потоковая передача через WebSockets

### 🧠 Работа с моделями ИИ

- Проект использует различные модели для кодогенерации и чатов (CodeLlama, Mistral, Qwen2 и др.)
- Основной интерфейс моделей реализован через llama.cpp (с версии 0.5.5)
- Поддерживаются различные бэкенды: CPU, CUDA, Metal, ROCm (AMD GPU)
- Модели размещаются в кэше `~/.tabby/models/`
- Поддерживаются HTTP API интеграции с: llama.cpp, ollama, mistral/codestral, openai

### 📊 Answer Engine и RAG

- Ретривал-аугментированная генерация кода (RAG) - ключевая особенность (с версии 0.3.0)
- Система использует индексированные репозитории для контекстно-зависимых дополнений
- Answer Engine обогащает ответы контекстом из репозиториев, issues и PRs
- Поддерживается веб-краулинг для дополнительного контекста (Developer Docs)
- Поиск активируется с помощью префиксов `@` (Developer Docs) и `#` (Repository Context)

### 🌐 Распределенная архитектура

- Поддержка распределенного выполнения моделей на разных машинах (с версии 0.6.0)
- Использование WebSockets для функций потоковой передачи (с версии 0.16.1)
- Конфигурируемый параметр `--parallelism` для контроля нагрузки и использования VRAM
- Поддержка выбора устройства для моделей (`--device`, `--chat-device`)

### 🔐 Система безопасности и доступа

- Встроенное управление пользователями с поддержкой SMTP (с версии 0.7.0)
- Интеграция с SSO (GitLab, GitHub) и самостоятельно размещенными экземплярами
- Поддержка групп пользователей с гранулярным контролем доступа (с версии 0.18.0)
- Система авторизации для доступа к API из IDE-расширений

### 💻 Поддерживаемые языки программирования

- Основная поддержка RAG (с 0.3.0): Rust, Python, JavaScript/TypeScript
- Дополнительная поддержка: Go (0.4.0), Ruby (0.4.0), OCaml (0.17.0), GraphQL (0.15.0)
- Специализированные инструменты индексации для каждого языка
- Поддержка подсветки синтаксиса в Code Browser

### 🏢 Enterprise Edition

- Компоненты `ee/` предоставляют расширенную функциональность для командной работы
- Включает аналитику использования, отчеты и статистику (вкладка "Reports", 0.10.0)
- Содержит страницу активностей для мониторинга использования (0.11.0)
- Хранит историю обсуждений в Answer Engine для совместного использования (0.16.1)

## Навигационные правила

### При работе с кодом

1. **Начинать с Tier 1** - основные компоненты для понимания архитектуры
2. **Изучать зависимости** - использовать `Cargo.toml` для понимания связей
3. **Следовать потоку данных** - от клиента через webserver к inference
4. **Проверять тесты** - они показывают примеры использования API
5. **Изучить исторические изменения** - использовать папку `.changes` для понимания эволюции

### Обновленная структура анализа

1. `crates/tabby/src/main.rs` - точка входа и CLI интерфейс
2. `crates/tabby-inference/` - логика инференса и работа с моделями
3. `crates/tabby-index/` - система индексирования для RAG
4. `ee/tabby-webserver/` - HTTP API, WebSockets и маршрутизация
5. `crates/tabby-crawler/` - анализ и индексирование репозиториев
6. `ee/tabby-db/` - хранение данных пользователей и активностей
7. `clients/` - интеграции с различными IDE

### Ключевые функциональные потоки

1. **Автодополнение кода**: IDE → API → Inference → RAG → Результат
2. **Чат/Answer Engine**: Веб-интерфейс → Chat API → Модель чата → RAG → Ответ
3. **Code Browser**: Веб-интерфейс → API → Индексированные репозитории → Результаты
4. **Управление пользователями**: Веб-интерфейс → API → База данных → SSO/SMTP

## Специфика Rust разработки

### Управление lifetimes

- Применять **техническую спецификацию управления lifetimes** (версия 2.0)
- Использовать минимально достаточную сложность lifetime
- Named lifetimes должны описывать архитектурную роль, не дублировать типы
- Приоритет: `IMPLICIT → ANONYMOUS '_ → NAMED → STATIC`

### Архитектурные принципы

- **Модульность**: каждый crate имеет четкую ответственность
- **Типобезопасность**: использовать сильную типизацию Rust
- **Производительность**: учитывать zero-cost abstractions и оптимизацию моделей
- **Безопасность**: избегать `unsafe` без крайней необходимости
- **Масштабируемость**: поддержка распределенных вычислений и инкрементального индексирования

### Code Review критерии

- Проверять правильность использования lifetimes по чеклисту
- Валидировать архитектурную семантику named lifetimes
- Контролировать публичные API на использование named lifetimes
- Избегать избыточной сложности в приватном коде
- Учитывать потенциальные узкие места производительности при работе с большими репозиториями

## Инструменты разработки

- **Cargo**: основной инструмент сборки
- **Clippy**: линтер для Rust кода  
- **Rustfmt**: форматирование кода
- **Турбо**: монорепо инструмент (turbo.json)
- **llama.cpp**: базовая библиотека для работы с моделями
- **tantivy**: движок поиска для индексирования

## Тестирование

- Юнит-тесты в каждом crate
- Интеграционные тесты в `tests/`
- Бенчмарки для производительности критичных компонентов
- Метрики для мониторинга через Prometheus (с версии 0.6.0)

## Документация

- Rustdoc комментарии для публичных API
- README.md в каждом значимом модуле
- Примеры использования в документации
- История изменений в папке `.changes` для отслеживания эволюции проекта
- MODEL_SPEC.md для спецификации поддерживаемых моделей

## Конфигурация и окружение

- Основные настройки в `config.toml`
- Переменные окружения для конфигурации (например, `TABBY_DOWNLOAD_HOST`, `TABBY_MODEL_CACHE_ROOT`)
- Флаги командной строки для конфигурации сервера (`--webserver`, `--device`, `--chat-model` и т.д.)
- Хранение данных в `~/.tabby/` (модели, индексы, репозитории)

## Ключевые эндпоинты API

- `/v1/completions` - API для автодополнения кода
- `/v1/chat/completions` - API для чата, совместимый с OpenAI
- `/metrics` - эндпоинт для сбора метрик Prometheus
- `/api/repositories` - управление репозиториями в Code Browser
- `/api/users` - управление пользователями (Enterprise Edition)
