# Правила проекта Tabby

## Специализация проекта

- **Основной язык**: Rust
- **Фокус**: Работа преимущественно с модулями на Rust
- **Архитектура**: Микросервисная архитектура с четким разделением ответственности

## Приоритетные модули для навигации

### 🚀 Основные компоненты (Tier 1)

```sh
crates/tabby/                 # Главный исполняемый модуль
crates/tabby-inference/       # Ядро системы инференса
crates/tabby-common/          # Общие утилиты и типы
ee/tabby-webserver/           # Веб-сервер (Enterprise Edition)
ee/tabby-schema/              # Схемы данных
```

### 🔧 Системные модули (Tier 2)  

```sh
crates/tabby-index/           # Индексация кода
crates/tabby-crawler/         # Сканирование репозиториев
crates/tabby-git/             # Интеграция с Git
ee/tabby-db/                  # База данных
```

### 📡 Клиентские интерфейсы (Tier 3)

```sh
clients/vscode/               # VS Code расширение
clients/tabby-agent/          # Агент для IDE
clients/tabby-chat-panel/     # Панель чата
```

### 🛠️ Вспомогательные модули (Tier 4)

```sh
crates/tabby-download/        # Загрузка моделей
crates/hash-ids/              # Хеширование
crates/http-api-bindings/     # HTTP API привязки
```

## Навигационные правила

### При работе с кодом

1. **Начинать с Tier 1** - основные компоненты для понимания архитектуры
2. **Изучать зависимости** - использовать `Cargo.toml` для понимания связей
3. **Следовать потоку данных** - от клиента через webserver к inference
4. **Проверять тесты** - они показывают примеры использования API

### Структура анализа

1. `crates/tabby/src/main.rs` - точка входа
2. `ee/tabby-webserver/` - HTTP API и маршрутизация  
3. `crates/tabby-inference/` - логика инференса
4. `crates/tabby-common/` - общие типы и утилиты

## Специфика Rust разработки

### Управление lifetimes

- Применять **техническую спецификацию управления lifetimes** (версия 2.0)
- Использовать минимально достаточную сложность lifetime
- Named lifetimes должны описывать архитектурную роль, не дублировать типы
- Приоритет: `IMPLICIT → ANONYMOUS '_ → NAMED → STATIC`

### Архитектурные принципы

- **Модульность**: каждый crate имеет четкую ответственность
- **Типобезопасность**: использовать сильную типизацию Rust
- **Производительность**: учитывать zero-cost abstractions
- **Безопасность**: избегать `unsafe` без крайней необходимости

### Code Review критерии

- Проверять правильность использования lifetimes по чеклисту
- Валидировать архитектурную семантику named lifetimes
- Контролировать публичные API на использование named lifetimes
- Избегать избыточной сложности в приватном коде
